Fixture records are generated by the existing SQLite Work services with synthetic data; no personal data or hardcoded mockup balances enter production. Native image/font/router/safe-area/Alert boundaries are substituted. Doubled CSS text is a stress proxy, **not OS Dynamic Type**. The evidence does not certify native modal gestures, focus, safe areas or performance.

## Reproduce

Use the installed project tooling and an existing local Playwright/Chromium installation:

```powershell
node --import tsx scripts/preview-client-details-v2.ts
node scripts/review-client-details-v2.cjs
```

The capture reviewer expects the genuine preserved before bundle at ignored `dist/client-details-v2-before`. It was built from the incumbent Client Details branch before the production integration changed. Do not recreate that bundle from the redesigned source and call it before evidence. On another checkout, recreate it from the pre-integration source using `$env:AXIS_CLIENT_PREVIEW_OUTPUT='dist/client-details-v2-before'`; the preview builder reads the actual components in that checkout. Clear that environment variable before building the after bundle. `AXIS_PLAYWRIGHT_PATH` and `AXIS_CHROMIUM_PATH` may select existing review tools; no dependency was added to Axis.

Financial writes are deliberately blocked in this browser fixture. The capture matrix checks navigation into the real editors, while the mounted SQLite tests exercise Save/Confirm, exact allocations, linked Income, Archive and Undo behavior. A browser click or platform export is not evidence of native runtime acceptance. See the [feature report](../../finance-work-client-details-v2.md) for the audit, validation and remaining device checks.
